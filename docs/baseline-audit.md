# Baseline audit — 2026-09-05

This is the requirement-to-evidence ledger for the supplied baseline task. A
number is reported only when the raw artifact records the relevant scope.
`Unknown` means that no measurement was found; it is never treated as zero.
The numerical gates below are adopted before further performance optimization,
using the better comparator in the available baseline. They are fixed historical
references; passing them alone cannot establish parity under a different
compositor. Fresh matched comparisons must also meet the better comparator
for each metric. Missing metrics remain ungated until their baseline is measured.

## Current private-compositor idle baseline

[`private-idle-three-terminal.json`](../bench/private-idle-three-terminal.json)
records three rotated fresh launches per terminal at each geometry, a printed
readiness marker, stable child-reported geometry throughout, and three-second
idle intervals. [`Summary`](../bench/private-idle-three-terminal-summary.json)
retains every host-memory sample and source hash. Weston 16.0.0 uses its private

measured. Linux 7.2.0 and Ryzen 9 7950X apply. Exact binary hashes, launch options,

These are **fixed historical-reference gates**, Foot's median and p90 for each
workload (the better comparator for each of these metrics). Table values are

distribution as well as pooled samples; one isolated passing run is insufficient.
The latest archive meets the median gate for Unicode and tabs, but misses
the text, ANSI and graphics medians and misses the p90 gate for text, ANSI and tabs. This
is a parser-barrier result, not a parity claim.

Reproduce the table (including the input SHA-256) with:

3. Run matched scrollback, resize, graphics upload/delete and window lifecycle
   soaks, recording peak and post-workload RSS/PSS/private/GPU memory. Keep

4. Instrument frame submission and compositor observation separately from PTY
   barriers; physical input/display latency requires a dedicated timestamped
   hardware/display method. The existing private Weston capture can be retained
   as a compositor-observed proxy only.

## Configuration provenance follow-up — search investigation

The earlier private resource collector inherited user configuration and recorded
CLI overrides, but did not preserve the full effective configuration. The local
Foot configuration remaps clipboard keys and sets DPI/font behavior. A later
search fixture uses an empty private XDG_CONFIG_HOME and explicit
`--config=/dev/null` for Foot. Existing resource values remain observations of
their recorded runs; effective font identity and complete configuration are
not proven by requested family names. Preserve all existing gates, but rerun
controlled configuration/font resource baselines before asserting competitive
parity. Search clipboard failures in private Weston are not performance data.

The controlled rerun is recorded in [`bench/private-idle-controlled.json`](../bench/private-idle-controlled.json) with grouped statistics in [`bench/private-idle-controlled-summary.json`](../bench/private-idle-controlled-summary.json). It uses private headless Weston only, three raw samples per terminal at 80x24 and 318x89, isolated XDG configuration, `/dev/null` Foot/Monstar configs, and the pinned DejaVu fontconfig directory. Every sampled Foot and Monstar resolver result selected the pinned `DejaVuSansMono.ttf`; this is resolver-proxy evidence and `actual_client_font` remains false. Comparator GPU process observations are null and unknown. These results are descriptive controlled provenance and do not alter the historical gates above.
